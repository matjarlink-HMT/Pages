# ٠٨ — الأمان والصلاحيات

## ١. مصفوفة الصلاحيات

الوحدة تستخدم **نفس نظام الأدوار والصلاحيات في متجرلينك** (Spatie Permission)، ولا تنشئ نظاماً موازياً. الصلاحيات مسبوقة بـ `shipping.`:

| الصلاحية | الوصف |
|---|---|
| `shipping.dashboard.view` | عرض لوحة التحكم |
| `shipping.shipments.view_all` | عرض كل الشحنات |
| `shipping.shipments.view_own` | عرض ما أنشأه المستخدم فقط |
| `shipping.shipments.create` | إنشاء شحنة |
| `shipping.shipments.update` | تعديل بيانات شحنة |
| `shipping.shipments.cancel` | إلغاء شحنة |
| `shipping.shipments.manual_event` | تسجيل حدث تتبع يدوي |
| `shipping.labels.print` | طباعة/تنزيل البوالص |
| `shipping.costs.view` | **رؤية التكاليف والهوامش** |
| `shipping.carriers.view` | عرض شركات الشحن |
| `shipping.carriers.manage` | إضافة/تعديل/تفعيل الحسابات |
| `shipping.carriers.credentials` | **إدخال/استبدال مفاتيح API** |
| `shipping.rates.manage` | المناطق وبطاقات الأسعار |
| `shipping.pickups.manage` | طلبات الاستلام |
| `shipping.returns.manage` | المرتجعات |
| `shipping.claims.manage` | المطالبات |
| `shipping.reports.view` | التقارير التشغيلية |
| `shipping.reports.financial` | التقارير المالية وتسوية COD |
| `shipping.settings.manage` | إعدادات الوحدة وقواعد الأتمتة |
| `shipping.logs.view` | سجلات API والـ Webhooks (تشخيص) |

**قرارات جوهرية:**
- **موظف الشحن لا يرى التكاليف.** يُنشئ ويطبع دون أن يعرف ما تدفعه الشركة — الحقول تُحذف من الرد لا تُخفى بـ CSS.
- **خدمة العملاء لا تنشئ شحنات** لكنها ترى كل شيء وتسجّل أحداثاً يدوية بعد اتصال بالشركة.
- **مفاتيح API لمدير النظام حصراً** — حتى مدير العمليات لا يملكها.
- الإخفاء في الواجهة تجميلي؛ **الفرض الحقيقي في `Policy` + `Resource`** على مستوى الخادم.

## ٢. عزل المستأجرين (Multi-Tenancy)

1. `TenantScope` عام على كل موديلات الوحدة — لا استعلام بلا `store_id` حتى لو نُسي في الكود.
2. `store_id` يُملأ تلقائياً عند الإنشاء من سياق الجلسة، **ولا يُقبل أبداً من مدخلات المستخدم**.
3. الروابط تستخدم `uuid` لا `id` تسلسلياً (يمنع التعداد).
4. كل `findOrFail` يمر عبر النطاق ← محاولة الوصول لشحنة متجر آخر تُرجع 404 لا 403 (لا تكشف الوجود).
5. اختبار تكامل إلزامي في CI: "متجر أ لا يرى بيانات متجر ب" لكل مسار.

## ٣. حماية بيانات اعتماد شركات الشحن

| الطبقة | الإجراء |
|---|---|
| التخزين | `encrypted:json` (AES-256-GCM) بمفتاح التطبيق؛ يُفضَّل مفتاح منفصل `SHIPPING_CREDENTIALS_KEY` قابل للتدوير |
| القراءة | تُفك داخل `CarrierRegistry` فقط، ولا تُمرَّر أبداً إلى طبقة العرض |
| العرض | مقنّعة دائماً `••••••3f21`؛ لا نقطة نهاية تُرجع القيمة الكاملة |
| التسجيل | `CredentialMasker` ينقّح كل `carrier_api_logs` وسجلات التطبيق |
| التعديل | كتابة فقط (استبدال)؛ كل تغيير يُسجَّل في سجل النشاط باسم المستخدم و IP |
| النسخ الاحتياطي | مشفّرة في النسخة، وتُستثنى من نسخ البيئات غير الإنتاجية |

## ٤. حماية الـ Webhooks

```
الطلب الوارد
  ├─ حد معدل لكل IP (١٢٠/دقيقة)
  ├─ قائمة IP بيضاء لكل شركة (إن وفّرتها)
  ├─ حفظ الحمولة الخام فوراً  ← قبل أي تحقق (لا نفقد شيئاً)
  ├─ تحقق التوقيع (HMAC-SHA256 مقارنة بزمن ثابت) → فشل: signature_valid=false + تنبيه أمني
  ├─ فحص النافذة الزمنية (±٥ دقائق) ← ضد إعادة الإرسال
  ├─ event_uid فريد ← ضد التكرار
  ├─ رد 200 فوراً
  └─ معالجة في طابور
```
لا تُشتق أي هوية من جسم الطلب قبل التحقق من التوقيع، ولا تُنفَّذ أي كتابة على الشحنة قبله.

## ٥. البوالص والملفات

- تُخزَّن على قرص **خاص** (`private`) لا `public`.
- الوصول عبر روابط موقّعة تنتهي خلال ١٥ دقيقة ومربوطة بالمستخدم.
- كل تنزيل يُسجَّل (من، متى، أي نسخة).
- فحص نوع MIME وحجم أقصى على أي ملف وارد من الشركة.
- ملفات الاستيراد (CSV) تُعالَج بمحلّل صارم مع حماية حقن الصيغ (`=`, `+`, `-`, `@` في بداية الخلية).

## ٦. حماية بيانات العملاء (PII)

| البيان | السياسة |
|---|---|
| الهاتف والعنوان | تُخزَّن كما هي (لازمة للتشغيل)، وتُقنَّع في التتبع العام والتصديرات لغير المخوّلين |
| صفحة التتبع العامة | تكشف: الحالة، السجل، الوعد، الشركة. **لا تكشف:** العنوان الكامل، الهاتف، التكلفة، الأصناف |
| البحث عن شحنة بلا تسجيل دخول | يتطلب رقم التتبع **+ آخر ٤ أرقام من الهاتف**، بخانق ٣٠/دقيقة و CAPTCHA بعد ٥ محاولات فاشلة |
| التصدير | يُسجَّل في سجل النشاط (من صدّر، أي فلاتر، كم صفاً) |
| الحذف | حذف ناعم؛ والحذف الفعلي وفق سياسة الاحتفاظ في المنصة بعد انتهاء الالتزام المحاسبي |

## ٧. سجل النشاط (Activity Log)

تُسجَّل تلقائياً عبر نفس نظام المنصة:

| الحدث | ما يُحفظ |
|---|---|
| إنشاء/إلغاء شحنة | المستخدم، الشحنة، الشركة، التكلفة، IP |
| طباعة/إعادة إصدار بوليصة | المستخدم، النسخة، الوقت |
| تغيير حالة يدوي | المستخدم، من ← إلى، السبب |
| ربط/تعديل حساب شركة | المستخدم، الشركة، **دون قيم المفاتيح** |
| تعديل تسعيرة أو قاعدة أتمتة | القيم قبل/بعد |
| تصدير بيانات | نطاق التصدير وعدد الصفوف |
| فشل تحقق Webhook | IP والحمولة الخام |

السجل غير قابل للتعديل من الواجهة، ويُعرض داخل صفحة الشحنة (ما يخصها) وفي سجل المنصة العام.

## ٨. ضوابط تقنية إضافية

| الضابط | التطبيق |
|---|---|
| حدود المعدل | إنشاء شحنة ٦٠/دقيقة للمستخدم · تسعير ١٢٠/دقيقة · تتبع عام ٣٠/دقيقة للـ IP |
| Idempotency | ترويسة `Idempotency-Key` إلزامية على إنشاء الشحنة |
| SSRF | عناوين Webhooks الصادرة تُتحقق: لا شبكات داخلية ولا `localhost` ولا `169.254.*` |
| حقن SQL | Eloquent + معاملات مربوطة؛ الفرز والفلترة من قائمة بيضاء معلنة لا من مدخلات حرة |
| XSS | Blade يهرّب افتراضاً؛ حقول الملاحظات تُنقّى، ولا `{!! !!}` على محتوى مستخدم |
| CSRF | مفعّل على مسارات اللوحة؛ Webhooks تُستثنى وتُحمى بالتوقيع بدلاً منه |
| مخرجات الشركات | تُعامل كمدخلات غير موثوقة: تحقق مخطط قبل الحفظ، وحد أقصى لحجم الرد |
| البيئات | `sandbox` مميّزة بشريط تحذير دائم في الواجهة ولا تُخلط شحناتها بالإنتاج |
| المراقبة | تنبيه عند: ارتفاع فشل نداءات شركة، تراكم طابور، فشل توقيع متكرر، شحنات عالقة في `pending_carrier` |
