# ٠٧ — تجربة المستخدم والتصميم

## ١. المبادئ الحاكمة

1. **الاندماج لا الإلحاق** — نفس الهيدر، نفس التنقل، نفس المكوّنات، نفس المسافات والألوان. لا إطار (iframe)، لا نافذة منبثقة لنظام آخر، لا هوية بصرية ثانية.
2. **الشاشة تجيب قبل أن تُسأل** — أول ما تراه: ما يحتاج تدخلك اليوم، لا جدول كل الشحنات منذ البداية.
3. **ثلاث نقرات كحد أقصى** من أي مكان إلى إنشاء شحنة أو معرفة حالة شحنة.
4. **لا شاشة فارغة بلا مخرج** — كل حالة فارغة تشرح وتقترح الخطوة التالية.
5. **الأرقام قابلة للنقر** — كل مؤشر في لوحة التحكم رابط لقائمة مفلترة مسبقاً.
6. **الأمان البصري** — الفعل المدمّر يحتاج تأكيداً، والفعل المكلف (إنشاء بوليصة) يعرض التكلفة قبل التنفيذ.

---

## ٢. معمارية المعلومات

```
متجرلينك ▸ الشحن
├── 📊 لوحة التحكم        ← الافتراضية
├── 📦 الشحنات            ← الجدول + الفلاتر + العمليات الدفعية
│    └── تفاصيل الشحنة    ← السجل الزمني + الإجراءات
├── ➕ إنشاء شحنة         ← معالج ٣ خطوات
├── ⚡ محطة الشحن          ← الوضع الدفعي (٨٠ طلباً صباحاً)
├── 🚚 شركات الشحن        ← الربط، الاختبار، الافتراضية، التغطية
├── 💰 التسعير            ← المناطق + بطاقات الأسعار + محاكي السعر
├── 🔁 المرتجعات
├── 📮 طلبات الاستلام
├── ⚖️ المطالبات
├── 📈 التقارير
└── ⚙️ إعدادات الشحن      ← الأتمتة، القوالب، المرسل الافتراضي
```

نقاط دخول من خارج الوحدة (مهمة للاندماج):
- **صفحة الطلب** → بطاقة "الشحن" مضمّنة: إنشاء شحنة / عرض التتبع.
- **قائمة الطلبات** → إجراء جماعي "شحن المحدد".
- **صفحة العميل** → كل شحنات هذا العميل.
- **لوحة المنصة الرئيسية** → بطاقة "شحنات تحتاج انتباهك".

## ٣. لوحة التحكم

**الصف الأول — يحتاج تدخلك الآن** (يُخفى إن كان صفراً — هذا مهم؛ الصفوف الفارغة ضجيج):
```
⚠️ متأخرة (٤)   ❗ فشل تسليم (٢)   🔇 بلا تحديث ٧٢س (٣)   🔴 فشل إرسال للشركة (١)
```
كل بطاقة بلون تحذيري وقابلة للنقر إلى قائمة مفلترة.

**الصف الثاني — مؤشرات التشغيل:**
| إجمالي الشحنات | جديدة | قيد الاستلام | أثناء النقل | خرجت للتسليم | تم التسليم | مرتجعة |

**الصف الثالث — مؤشرات مالية وأداء:**
| إجمالي تكلفة الشحن | متوسط تكلفة الشحنة | متوسط مدة التوصيل | نسبة التسليم في الموعد | تحصيل COD المعلّق |

كل مؤشر يعرض **الاتجاه مقابل الفترة السابقة** (▲ ١٢٪) — الرقم وحده بلا سياق لا يقود قراراً.

**الرسوم:**
- خط: الشحنات والتكلفة عبر الزمن (محوران).
- أعمدة أفقية: أكثر ١٠ ولايات شحناً.
- حلقي: توزيع الشحنات على شركات الشحن.
- بطاقة "أفضل شركة شحن" بمعيار مركّب معلن (لا رقم سحري): نسبة نجاح × الالتزام بالموعد ÷ التكلفة النسبية.

**ملاحظة تصميم:** الفترة الافتراضية آخر ٣٠ يوماً، والمقارنة بالـ ٣٠ السابقة. مبدّل الفترة ثابت أعلى الصفحة ويطبّق على كل شيء بما فيه الرسوم.

## ٤. جدول الشحنات

**شريط علوي:** بحث موحّد (رقم طلب / رقم تتبع / اسم عميل / هاتف) + فلاتر سريعة كرقائق (Chips): `الكل · تحتاج انتباهك · اليوم · متأخرة · COD · لم تُستلم بعد`.

**الأعمدة:** المرجع · رقم الطلب · رقم التتبع (نسخ بنقرة) · الشركة (شعار) · العميل · الولاية · التاريخ · الحالة (شارة ملوّنة) · آخر تحديث (نسبي: "قبل ساعتين") · التكلفة.

**التفاعل:**
- تحديد متعدد → شريط إجراءات عائم: طباعة بوالص · تحديث الحالة · جدولة استلام · تصدير.
- نقرة على الصف → لوحة جانبية (Drawer) بالملخص دون مغادرة الجدول ← وهذا يوفّر معظم النقرات في عمل خدمة العملاء.
- أعمدة قابلة للإخفاء وترتيب محفوظ لكل مستخدم.
- الترقيم بالمؤشر مع "تحميل المزيد" (لا أرقام صفحات — الجداول الكبيرة).
- اختصارات: `/` بحث · `n` شحنة جديدة · `j/k` تنقل · `Enter` فتح.

**الحالة الفارغة الأولى:** "لم تُنشئ أي شحنة بعد — اربط شركة شحن أولاً" مع زرين: [ربط شركة] [إنشاء شحنة تجريبية].

## ٥. معالج إنشاء الشحنة (٣ خطوات)

```
① البيانات  →  ② اختيار الشركة  →  ③ التأكيد والطباعة
```

**الخطوة ١ — البيانات:**
- **إن أتت من طلب:** كل شيء مُعبّأ مسبقاً وقابل للطي؛ يظهر فقط ما يحتاج انتباهاً (الوزن). هذا جوهر وعد "لا إدخال مرتين".
- المرسل: منتقى من دفتر العناوين، الافتراضي محدد سلفاً.
- المستلم: المحافظة → الولاية (قائمة مترابطة) + معلم بارز + إحداثيات اختيارية من الخريطة.
- الطرد: الوزن، الأبعاد، عدد القطع، القيمة. **يُحسب الوزن الحجمي مباشرة أمام المستخدم** ويُعرض "الوزن المحتسب: ٣.٢ كجم" — يمنع مفاجأة الفاتورة لاحقاً.
- COD: مفتاح تشغيل يملأ المبلغ من إجمالي الطلب تلقائياً.

**الخطوة ٢ — اختيار الشركة (الشاشة الأهم):**
بطاقات لكل عرض، مرتّبة بالتوصية:
```
┌────────────────────────────────────────────────┐
│ [شعار] أسياد إكسبريس — توصيل سريع    ⭐ الأنسب │
│ ٢.١٥٠ ر.ع        ١–٢ يوم عمل                   │
│ نجاح ٩٦٪ · في الموعد ٩١٪ · تقييمك ٤.٦          │
│ ✓ تتبع مباشر  ✓ COD  ✓ تأمين حتى ٥٠ ر.ع        │
│                                   [ اختيار ]   │
└────────────────────────────────────────────────┘
```
- الأسعار تصل تباعاً مع هياكل تحميل (Skeleton) — لا انتظار لأبطأ شركة.
- الشركات غير المتاحة أسفل القائمة **مع السبب** ("لا تغطي ظفار"، "تعذّر الاتصال").
- تبديل "عرض كجدول مقارنة" لمن يفضّل المقارنة العمودية.
- شارة توفير: "أرخص بـ ٠.٦٠٠ ر.ع من خيارك المعتاد".

**الخطوة ٣ — التأكيد:**
ملخص أخير + التكلفة الإجمالية بوضوح + [تأكيد وإنشاء البوليصة]. بعد النجاح:
شاشة نجاح فيها رقم التتبع (نسخ بنقرة)، معاينة البوليصة، وأزرار: [طباعة] [تنزيل PDF] [إرسال التتبع للعميل] [شحنة جديدة] [العودة للطلب].

**منع الازدواج:** زر التأكيد يُقفل فوراً، وإعادة إرسال نفس البيانات تُرجع نفس الشحنة بدل إنشاء ثانية.

## ٦. تفاصيل الشحنة

تخطيط عمودين:

**اليمين (الأساسي):**
- ترويسة: المرجع · شارة الحالة · رقم التتبع · [تحديث الآن]
- شريط تقدّم أفقي للمراحل: إنشاء ← استلام ← نقل ← خرجت للتسليم ← تسليم (المرحلة الحالية مضيئة، والمسار الاستثنائي يتفرّع بلون تحذيري)
- **السجل الزمني الكامل:** كل حدث بوقته وموقعه ومصدره (Webhook/يدوي/مزامنة) وصورة الاسم لمن سجّله يدوياً
- الأصناف والقطع

**اليسار (السياق والإجراءات):**
- بطاقة العميل (اتصال/واتساب بنقرة)
- بطاقة المرسل
- بطاقة الشركة والخدمة
- بطاقة التكاليف: المُسعّر · الفعلي · رسوم COD · **فرق** (يُبرز بالأحمر إن وُجد)
- بطاقة الطلب المرتبط (رابط للطلب)
- الإجراءات: طباعة بوليصة · إعادة إصدار · إلغاء · فتح مطالبة · إنشاء مرتجع · إضافة حدث يدوي · نسخ رابط التتبع للعميل
- الإشعارات المرسلة: القناة والحالة وزر إعادة إرسال

## ٧. محطة الشحن (الوضع الدفعي)

للتاجر الذي يشحن ٨٠ طلباً صباحاً — شاشة مختلفة كلياً عن المعالج:
```
[قائمة الطلبات الجاهزة ▸ تحديد الكل]
   ↓
[تطبيق قواعد الاختيار التلقائي] → كل طلب تُقترح له شركة وسعر
   ↓
[مراجعة الاستثناءات فقط] ← ما لم تُطابقه قاعدة أو يحتاج وزناً
   ↓
[إنشاء الكل] → شريط تقدّم حي (٦٣/٨٠)
   ↓
[بوليصة واحدة PDF مدموجة] + [قائمة تجميع] + [جدولة استلام لكل شركة]
```
+ وضع مسح الباركود: مسح الطرد → تأكيد التغليف → تحديث الحالة بلا لمس فأرة.

## ٨. شركات الشحن

بطاقة لكل شركة:
```
┌──────────────────────────────────────────┐
│ [شعار] أرامكس            ● متصل          │
│ آخر فحص: قبل ١٠ دقائق                     │
│ ١٢٤ شحنة هذا الشهر · نجاح ٩٤٪              │
│ [اختبار الاتصال] [الإعدادات] [⋯]         │
└──────────────────────────────────────────┘
```
- **حالة الاتصال بلون صريح:** أخضر متصل · أحمر فشل (مع سبب مقروء عربي) · رمادي غير مربوط.
- نموذج الربط **يُبنى من `credential_schema`** — لا نموذج مكتوب يدوياً لكل شركة.
- بعد الحفظ: اختبار اتصال تلقائي فوري ولا يُفعّل الحساب إلا بعد نجاحه (أو تفعيل يدوي صريح).
- المفاتيح تُعرض مقنّعة دائماً `••••••3f21` مع [استبدال] لا [إظهار].
- تبويب "التغطية": الولايات المدعومة (خريطة عُمان مظللة + قائمة).
- شركة "توصيل يدوي" تُضاف بنفس الشكل بلا مفاتيح — فقط تسعيرة ومناطق.

## ٩. نظام الحالات البصري

| الحالة | اللون | الشارة |
|---|---|---|
| مسودة / بانتظار الشركة | رمادي | `b-gray` |
| تم الإنشاء | أزرق | `b-blue` |
| تم الاستلام / أثناء النقل | بنفسجي | `b-purple` |
| خرجت للتسليم | برتقالي | `b-amber` |
| تم التسليم | أخضر | `b-green` |
| فشل تسليم / استثناء / خطأ | أحمر | `b-red` |
| مرتجعة / ملغاة | رمادي داكن | `b-gray` |

قواعد ثابتة: **لون واحد لكل حالة في كل الشاشات** · الحالة نص + لون (لا لون وحده — إتاحة لعمى الألوان) · المتأخر يُعرض كشارة ثانية مستقلة لا كحالة.

## ١٠. الاستجابة (Responsive)

| الشاشة | التكيّف |
|---|---|
| ≥ ١٢٠٠px | تخطيط كامل بعمودين وجدول بكل الأعمدة |
| ٧٦٨–١١٩٩ | عمود واحد، الجدول بأعمدة أساسية، الباقي في الصف الموسّع |
| < ٧٦٨ | **الجدول يصبح بطاقات** لا جدولاً مضغوطاً؛ شريط إجراءات سفلي ثابت؛ المعالج خطوة كاملة لكل شاشة |

الموبايل ليس عرضاً مصغّراً: موظف الشحن يستخدم الهاتف للمسح والتحديث الميداني، لذا أزرار المسح والتحديث السريع أكبر وأقرب لليد.

---

## ١١. اللغة والاتجاه

- عربي RTL افتراضاً، وإنجليزي LTR بالتبديل — كل التخطيطات بخصائص منطقية (`margin-inline-start` لا `margin-left`).
- الأرقام إنجليزية (٠١٢٣ مقابل 0123): تُستخدم **الأرقام اللاتينية** للأرقام المالية وأرقام التتبع لسهولة القراءة والنسخ، والنص عربي.
- التواريخ: ميلادية بصيغة مقروءة + وقت نسبي ("قبل ٣ ساعات") مع التاريخ الكامل عند التحويم.
- التكلفة دائماً بالريال العُماني بثلاث خانات: `٢.١٥٠ ر.ع`.

---

## ١٢. الأداء المُدرَك

- هياكل تحميل (Skeletons) لا دوّامات (Spinners).
- تحديثات متفائلة (Optimistic) لتغيير الحالة اليدوي مع تراجع عند الفشل.
- عروض الأسعار تظهر تباعاً كل عرض فور وصوله.
- التصدير وطباعة الدفعات دائماً في الخلفية مع إشعار عند الجاهزية — لا تجميد للشاشة.
- الجداول الطويلة بتحميل تدريجي.

## ١٣. الحالات الفارغة والأخطاء

| الموقف | ما يُعرض |
|---|---|
| لا شركات مربوطة | شرح + [ربط أول شركة] + شرح الفارق بين API ويدوي |
| لا شحنات | [إنشاء شحنة] + [استيراد من الطلبات] |
| لا نتائج بحث | "لا نتائج لـ «…»" + [مسح الفلاتر] |
| فشل التسعير كلياً | "تعذّر جلب الأسعار الآن" + [إعادة المحاولة] + [متابعة بسعر يدوي] ← **دائماً مخرج** |
| بيانات اعتماد خاطئة | رسالة صريحة + رابط مباشر لإعدادات الحساب |
| شحنة بلا تحديث | "لم تُحدّث الشركة الحالة منذ ٧٢ ساعة" + [تحديث الآن] + [تواصل مع الشركة: ٢٤xxxxxx] |
