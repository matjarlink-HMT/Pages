# وحدة إدارة الشحن — متجرلينك (MatjarLink Shipping Module)

حزمة التصميم الهندسي الكاملة لوحدة الشحن المدمجة داخل منصة متجرلينك.

> **الحالة:** تصميم معتمد للمراجعة — التنفيذ الفعلي للخلفية (Laravel) يبدأ بعد اعتماد هذه الوثائق.
> يرافق هذه الوثائق **نموذج تفاعلي** (`shipping.html`) يعرض الشاشات الحقيقية للتجربة والاعتماد البصري قبل كتابة كود المنصة.

---

## القرارات المعمارية المعتمدة

| القرار | الاختيار | السبب المختصر |
|---|---|---|
| المكدس التقني | Laravel 11 + MySQL 8 | مكدس منصة متجرلينك الحالي؛ Queues/Events/Scheduler جاهزة لعمليات التتبع والWebhooks |
| نمط الوحدة | Modular Monolith — `app/Domains/Shipping` | عزل كامل للنطاق مع بقاء المعاملات (Transactions) والصلاحيات وقاعدة البيانات مشتركة مع المنصة |
| تكامل شركات الشحن | Driver/Adapter Contract + Registry | إضافة أي شركة جديدة = ملف واحد + سطر تسجيل، بدون لمس النواة |
| الشركات بدون API | Manual Driver + Rate Card Engine | التاجر يدير المندوبين وشركات التوصيل الصغيرة داخل نفس الشاشات |
| تحديث الحالات | Webhook أولاً، Polling تكيّفي احتياطاً | تقليل استهلاك الـ API مع ضمان عدم فقدان أي حدث |
| الواجهة | نفس Design System للمنصة (Blade + Livewire 3 + Alpine) | تشعر أنها جزء أصيل من متجرلينك لا نظام منفصل |
| العزل | Tenant Global Scope على `store_id` في كل جدول | أمان متعدد المستأجرين بشكل افتراضي لا اختياري |

## النموذج التفاعلي

`shipping.html` في جذر المستودع — يفتح من صفحة متجرلينك. يعرض:

- لوحة تحكم بمؤشرات حيّة ورسوم بيانية
- جدول الشحنات مع بحث وفلترة وفرز وتصدير
- صفحة تفاصيل الشحنة بالسجل الزمني الكامل
- معالج إنشاء شحنة من ٣ خطوات مع مقارنة أسعار حيّة
- إدارة شركات الشحن واختبار الاتصال
- تقارير ومقارنة أداء شركات الشحن

النموذج يعمل ببيانات وهمية داخل المتصفح (localStorage) — غرضه **اعتماد التجربة والتصميم**، وليس تنفيذ المنطق الحقيقي.
