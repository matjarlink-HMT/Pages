# ١٠ — خارطة التنفيذ

كل مرحلة تُسلَّم **عاملة وقابلة للاستخدام** لا نصف ميزة. الترتيب مبني على: ما الذي يجعل الوحدة مفيدة أبكر؟

---

## المرحلة ٠ — الأساس (٣–٤ أيام)

- الهجرات الأساسية: `shipping_carriers`, `store_carrier_accounts`, `shipments`, `shipment_addresses`, `shipment_packages`, `shipment_items`, `shipment_events`, `carrier_status_maps`
- `ShipmentStatus` Enum + آلة الحالات + `ShipmentEventRecorder`
- عقد `CarrierDriver` + `CarrierRegistry` + `AbstractCarrierDriver`
- `ManualDriver` كامل (أول Driver عامل — يثبت أن العقد صحيح قبل بناء تكامل حقيقي)
- الصلاحيات والسياسات + `TenantScope`
- بذر المحافظات والولايات العُمانية

**معيار القبول:** إنشاء شحنة يدوية عبر Tinker، تسجيل أحداث، وانتقال الحالة صحيح ومُدقَّق.

---

## المرحلة ١ — الحد الأدنى العامل (٧–٩ أيام)

- إنشاء شحنة (معالج ٣ خطوات) + التكامل مع الطلب (تعبئة مسبقة، حفظ رقم التتبع)
- بوليصة PDF (قالب داخلي A4 و10×15 بباركود)
- جدول الشحنات: بحث، فلترة، فرز، ترقيم بالمؤشر
- صفحة تفاصيل الشحنة بالسجل الزمني
- إدارة شركات الشحن: ربط، اختبار اتصال، تفعيل، افتراضية
- لوحة تحكم أولية (مؤشرات + صف "تحتاج انتباهك")
- `RateCardEngine` + المناطق + بطاقات الأسعار
- سجل النشاط

**معيار القبول:** تاجر يستطيع تشغيل عملياته كاملة بشركة يدوية واحدة دون أي API.

---

## المرحلة ٢ — أول تكاملين حقيقيين (٧–٩ أيام)

- Driver لشركة محلية عُمانية + Driver لشركة إقليمية (يُثبت أن العقد يستوعب نمطين مختلفين)
- تسعير حي + شاشة المقارنة + `rate_quotes`
- استقبال Webhooks (تحقق توقيع، حفظ خام، معالجة في طابور، إعادة تشغيل)
- Polling تكيّفي + Circuit Breaker + `carrier_api_logs`
- إلغاء الشحنة لدى الشركة
- الإشعارات: بريد + داخل النظام

**معيار القبول:** شحنة تُنشأ فعلياً لدى شركة حقيقية، وتتحدّث حالتها تلقائياً دون تدخل، والحالة تنعكس على الطلب.

---

## المرحلة ٣ — التشغيل بحجم حقيقي (٦–٨ أيام)

- محطة الشحن الدفعية + دمج البوالص PDF
- محرك الاختيار التلقائي (`AutomationRuleEngine`)
- محرك SLA + كشف المتأخر والصامت
- إشعارات SMS وواتساب + قوالب قابلة للتحرير
- صفحة التتبع العامة بعلامة المتجر
- طلبات الاستلام (Pickup)
- تصدير الشحنات (غير متزامن)

**معيار القبول:** ٨٠ طلباً → بوالص مطبوعة في أقل من ١٠ دقائق، والعميل يتلقى إشعاراته تلقائياً.

---

## المرحلة ٤ — الذكاء والمال (٦–٧ أيام)

- `carrier_performance_daily` + مهمة التجميع
- منظومة التقارير كاملة (١١ تقريراً) + تصدير CSV/Excel/PDF
- بطاقة أداء شركات الشحن ومقارنتها
- تسوية COD + استيراد كشوف الشركات
- مطابقة فواتير الشحن (كشف الفروقات)
- توصية ذكية في المقارنة مبنية على الأداء الفعلي

**معيار القبول:** التاجر يجيب من الشاشة: كم أنفقت؟ من أفضل شركة؟ أين أخسر مالاً؟

---

## المرحلة ٥ — التوسّع (٧–٩ أيام)

- المرتجعات كاملة + بوابة العميل
- المطالبات (Claims)
- Drivers إضافية (٢–٣ شركات)
- API خارجي للشركاء + Webhooks صادرة + مفاتيح API
- تعدد المستودعات
- ترجمة إنجليزية كاملة

---

## المخاطر وتخفيفها

| الخطر | الاحتمال | الأثر | التخفيف |
|---|---|---|---|
| توثيق شركات الشحن ناقص أو غير دقيق | **عالٍ** | تأخير التكاملات | ابدأ بـ `ManualDriver` — الوحدة تعمل بلا أي API؛ اطلب بيئة اختبار مبكراً؛ اكتب Fixtures من الردود الفعلية |
| تأخر الحصول على بيانات اعتماد الشركات | عالٍ | تعطّل المرحلة ٢ | ابدأ إجراءات الحسابات التجارية **بالتوازي مع المرحلة ٠** لا بعدها |
| اختلاف تسميات الحالات بين الشركات | متوسط | حالات خاطئة | خريطة الحالات في قاعدة البيانات + قائمة "رموز غير معيّنة" مرئية للعمليات |
| Webhooks غير مدعومة لدى شركة محلية | متوسط | تأخر التحديث | Polling تكيّفي جاهز كبديل كامل، وتحديث يدوي متاح دائماً |
| تكرار البوالص والرسوم | متوسط | خسارة مالية | `idempotency_key` + قفل الطلب منذ المرحلة ١ لا لاحقاً |
| تضخم النطاق | **عالٍ** | تأخر الإطلاق | حدود النطاق موثّقة في `01-analysis.md §5`؛ كل إضافة تمر بالفئات في `09-enhancements.md` |
| أداء الجداول عند النمو | منخفض | بطء | الفهارس وجدول التجميع مصمّمان منذ اليوم الأول |

---

## بوابات الجودة (لكل مرحلة)

- تغطية اختبارات ≥ ٨٠٪ لطبقتي Services وDomain
- كل Driver مغطّى باختبارات مقابل ردود محفوظة (بلا شبكة)
- اختبار عزل المستأجرين إلزامي في CI
- مراجعة أمنية عند: بيانات الاعتماد، الـ Webhooks، التتبع العام
- قياس أداء: لوحة التحكم < ٤٠٠ مللي، جدول الشحنات < ٣٠٠ مللي على ١٠٠ ألف صف
- توثيق API محدَّث مع كل مرحلة
