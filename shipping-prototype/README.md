# وحدة إدارة الشحن — نموذج مستقل

نموذج تفاعلي قائم بذاته لوحدة الشحن. **مستقل تماماً**: لا يشارك HMT OS ولا أي منصة أخرى ملفاً واحداً — هيدره وأنماطه ونواته البرمجية كلها هنا.

الغرض: تجربة الشاشات واعتماد التصميم وتجربة المستخدم **قبل** الدمج في منصة متجرلينك.

---

## التشغيل

افتح `index.html` في المتصفح. لا خادم، لا بناء، لا اعتماديات — ملف يُفتح بالنقر المزدوج.

للتشغيل عبر خادم محلي (اختياري):

```bash
python3 -m http.server 8080   # ثم افتح http://localhost:8080/shipping-prototype/
```

## الملفات

```
shipping-prototype/
├── index.html          الصفحة الوحيدة — الهيدر والتبويبات وهيكل الشاشات
└── assets/
    ├── app.css         الهوية والمكوّنات كاملة (وضع فاتح وداكن)
    ├── ui.js           نواة صغيرة: تخزين، إشعارات، تبويبات، رسم خطي، مبدّل العرض
    ├── data.js         البيانات المرجعية (شركات الشحن، جغرافيا عُمان) ومولّد البيانات
    └── app.js          منطق الشاشات
```

كل قيمة لونية في `app.css` معرّفة في كتلة رموز واحدة أعلى الملف. **تبديل الهوية إلى ألوان متجرلينك عند الدمج تعديل في مكان واحد**، ولا يمس بقية الملف.

## الشاشات

| الشاشة | ما تُظهره |
|---|---|
| **لوحة التحكم** | صف «تحتاج انتباهك» (متأخرة / فشل تسليم / صامتة / فشل إرسال) قابل للنقر، ١٤ مؤشراً باتجاه مقارنة بالفترة السابقة، ورسوم للحجم والتكلفة والولايات وتوزيع الشركات |
| **الشحنات** | جدول ٢٤٠ شحنة: بحث موحّد، رقائق فلترة، فرز بكل عمود، تحديد جماعي، تصدير CSV، تحميل تدريجي |
| **تفاصيل الشحنة** | لوحة جانبية: مراحل الشحنة، السجل الزمني الكامل بمصدر كل حدث، التكاليف مع إبراز فرق الفوترة، وإجراءات (تحديث، بوليصة، إلغاء، حدث يدوي) |
| **إنشاء شحنة** | معالج ٣ خطوات، حساب الوزن الحجمي أثناء الإدخال، مقارنة أسعار مرتّبة بالتقييم المركّب مع **عرض أسباب** عدم توفّر الشركات |
| **شركات الشحن** | حالة الربط، اختبار اتصال، تفعيل/تعطيل، تحديد الافتراضية، مفاتيح مقنّعة |
| **التقارير** | مقارنة أداء الشركات، أكثر الولايات والعملاء، التكلفة حسب الشهر، ونسب التأخير والإرجاع وفروقات الفواتير |

## البيانات

مولّدة داخل المتصفح ببذرة ثابتة — نفس الأرقام في كل فتح، فالمقارنة بين الجلسات ممكنة. لا شيء يُرسل إلى أي خادم. زر **«إعادة توليد البيانات»** يعيد الحالة من الصفر.

تُحفظ الحالة في `localStorage`، ومع تعذّر الوصول إليه (بعض بيئات المعاينة المعزولة) تنتقل تلقائياً إلى ذاكرة الجلسة فتعمل الشاشات كاملة وتضيع البيانات عند الإغلاق فقط.

## حدود النموذج

نموذج واجهة لا نظام حقيقي: لا اتصال بشركات شحن، ولا بوالص PDF فعلية، ولا إشعارات. الأزرار التي تحاكي عملية خارجية تُظهر رسالة بدل تنفيذها.

المنطق الحقيقي وقواعد البيانات في:

- [`../docs/shipping-module/`](../docs/shipping-module/README.md) — التصميم الهندسي الكامل
- [`../matjarlink-shipping/`](../matjarlink-shipping/README.md) — التنفيذ بمكدس متجرلينك (Laravel + MySQL)

## عند الدمج في متجرلينك

هذا النموذج مرجع بصري، والتنفيذ الفعلي جاهز في `matjarlink-shipping/`. خطوات الدمج:

1. نسخ حزمة Laravel إلى تطبيق متجرلينك وتسجيل مزوّد الخدمة.
2. تبديل كتلة الرموز اللونية إلى هوية متجرلينك.
3. جعل قالب الوحدة يمتد القالب الرئيسي للمنصة ليرث الهيدر والتنقل.
